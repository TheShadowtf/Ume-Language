JSON

JSON serialization in Ume is compile-time generated. Apply [Serializable] to a class and the compiler writes toJsonString() and fromJsonString() methods for you — no runtime reflection, no manual parsing. Use [JsonProperty("key")] on fields to override the JSON key name.

Quick start

// No import needed — attributes are built-in keywords

[Serializable]
public class User {
    [JsonProperty("user_id")]
    public int id;

    [JsonProperty("username")]
    public string name;

    public double score;   // uses field name "score" as JSON key
}

public class Main {
    public static func void main() {
        var u = new User();
        u.id    = 1;
        u.name  = "Alice";
        u.score = 98.5;

        // Serialize → JSON string
        string json = u.toJsonString();
        Console.println(json);
        // {"user_id":1,"username":"Alice","score":98.5}

        // Deserialize ← JSON string
        var u2 = User.fromJsonString(json);
        Console.println(u2.name);    // Alice
        Console.println(u2.score);   // 98.5
    }
}

The two attributes

AttributeApplies toEffect
[Serializable]ClassGenerates toJsonString() and fromJsonString(string) methods.
[JsonProperty("key")]FieldOverrides the JSON key for that field. Without it, the field's name is used.

How it works

When the compiler sees [Serializable] on a class, it scans the class's public fields and generates serialization code at compile time. Each field becomes a key-value pair in the output JSON. The generated toJsonString() walks the fields in declaration order and builds the JSON string; fromJsonString() parses the JSON and assigns each parsed value back to the corresponding field. The implementation lives in the compiler's code-generation pass, so the runtime cost is just the serialization itself — no reflection overhead.

Renaming keys

The most common use of [JsonProperty] is mapping between Ume's preferred naming (often camelCase or descriptive) and a JSON schema you must conform to (often snake_case or abbreviated):

[Serializable]
public class Product {
    [JsonProperty("product_id")]    public int id;
    [JsonProperty("display_name")]  public string name;
    [JsonProperty("price_usd")]     public double price;
    [JsonProperty("in_stock")]      public bool inStock;
}

var p = new Product();
p.id = 101;
p.name = "Widget";
p.price = 19.99;
p.inStock = true;

Console.println(p.toJsonString());
// {"product_id":101,"display_name":"Widget","price_usd":19.99,"in_stock":true}

Round-tripping

Serialization is symmetric: fromJsonString(toJsonString(obj)) produces an object equal to obj in all the serialized fields. This makes JSON a convenient format for persisting objects to disk or sending them over a network:

// Save
[Serializable]
public class GameSave {
    public string playerName;
    public int level;
    public double score;
    public List<int> inventory;
}

var save = new GameSave();
save.playerName = "Alice";
save.level = 7;
save.score = 12500.0;
save.inventory = new List<int>();
save.inventory.add(1); save.inventory.add(5); save.inventory.add(12);

File f = new File("save.json");
f.write(save.toJsonString());

// Load
var loaded = GameSave.fromJsonString(f.readAll());
Console.println($"Welcome back, {loaded.playerName} (level {loaded.level})");

Nested objects

If a [Serializable] class has a field whose type is another [Serializable] class, the nested object is serialized recursively — the inner object's toJsonString() is embedded in the outer object's JSON. This lets you build up complex object graphs and serialize them in one call.

[Serializable]
public class Address {
    public string street;
    public string city;
}

[Serializable]
public class Person {
    public string name;
    public Address address;   // nested serializable
}

var p = new Person();
p.name = "Alice";
p.address = new Address();
p.address.street = "123 Main St";
p.address.city = "Springfield";

Console.println(p.toJsonString());
// Note: Nested serializable objects may show as [Address instance] in the
// current interpreter version. The top-level fields serialize correctly.
// For full nested serialization, flatten the object or serialize manually.
No runtime reflection

Because the serialization code is generated at compile time, there's no runtime cost for inspecting the class layout. The generated code is just direct field reads and writes — as fast as hand-written serialization.
