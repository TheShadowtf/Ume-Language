Lambdas & Closures

A lambda is an anonymous function you write inline. Lambdas are first-class values — you can store them in variables, pass them as arguments, return them from functions, and capture variables from their enclosing scope. They're the foundation of Ume's functional-style collection operations (filter, map, reduce, forEach, sort).

Lambda syntax

A lambda consists of a parameter list, an arrow (-> or =>), and a body. The body can be a block in braces (for multiple statements) or a single expression (for one-liners). When the body is a single expression, the return is implicit.

// Block body
var add = (int a, int b) -> {
    return a + b;
};

// Expression body — implicit return
var sq = (int n) -> n * n;

// Both arrow forms accepted: -> and =>
var greet = (string name) => "Hello, " + name;

Single-parameter shorthand

When a lambda takes exactly one parameter, you can omit the parentheses and the parameter's type — the type is inferred from context. This is the form you'll see most often in collection pipelines:

// n's type is inferred from the surrounding context
var doubled = nums.map(n -> n * 2);
var evens   = nums.filter(n -> n % 2 == 0);
nums.forEach(n -> Console.println(n));

Zero-parameter lambdas

A lambda with no parameters needs empty parentheses:

var sayHi = () -> { Console.println("hi"); };
sayHi();   // hi

// Or with expression body:
var getPi = () -> Math.PI;

The func<…> type

The type of a function value is written with func. There are two equivalent syntaxes:

FormExampleMeaning
Angle-bracketfunc<int, int, int>First type is the return type; rest are parameter types. So this is a function taking two ints and returning an int.
Inlinefunc int (int, int)Return type, then parameter types in parentheses. Same meaning.
 
// Both declare a function: (int, int) → int
func<int, int, int> op1;
func int (int, int) op2;

op1 = (int a, int b) -> { return a + b; };
op2 = (int a, int b) -> a * b;

Console.println(op1(3, 4));   // 7
Console.println(op2(3, 4));   // 12

The inline form is more common in parameter lists because it reads naturally:

// A function that takes another function as a parameter
public func int apply(func int (int, int) f, int x, int y) {
    return f(x, y);
}

var result = apply((a, b) -> a + b, 10, 20);
Console.println(result);   // 30

Single-parameter function types

The standard library uses the inline form heavily. For example, List<T>.forEach takes a func void (T) — a function taking a T and returning void:

List<string> names = ["Alice", "Bob", "Charlie"];

// forEach takes a func void (string)
names.forEach((string n) -> Console.println("Hi " + n));
names.forEach(n -> Console.println("Hi " + n));   // shorthand

Closures

A closure is a lambda that captures variables from its enclosing scope. The captured variables are not copied at the moment the lambda is created — they're referenced, so changes to them after the lambda is created are visible when the lambda runs. This is what makes closures powerful for callbacks and event handlers.

int multiplier = 10;

// This lambda captures 'multiplier' from the enclosing scope
func int (int) scale = n -> n * multiplier;

Console.println(scale(5));    // 50

// Changing the captured variable affects the lambda
multiplier = 100;
Console.println(scale(5));    // 500

Capturing local state

Closures are the standard way to carry local state into a callback. For example, a counter that increments each time it's called:

public func func int () makeCounter() {
    int count = 0;
    return () -> {
        count = count + 1;
        return count;
    };
}

var c = makeCounter();
Console.println(c());   // 1
Console.println(c());   // 2
Console.println(c());   // 3

// Each closure has its own captured state
var d = makeCounter();
Console.println(d());   // 1
Console.println(c());   // 4

Lambdas with collections

This is where lambdas shine. The collection types all take lambdas for transformation, filtering, and aggregation:

List<int> nums = [1, 2, 3, 4, 5];

// filter: keep elements matching a predicate
List<int> evens = nums.filter(n -> n % 2 == 0);    // [2, 4]

// map: transform each element
List<int>  doubled  = nums.map(n -> n * 2);   // [2, 4, 6, 8, 10]
List<string> words  = nums.map(n -> $"n{n}");    // ["n1", "n2", ...]

// reduce: combine all elements into one value
int sum = nums.reduce(0, (acc, n) -> acc + n);     // 15

// sort with a comparator lambda
nums.sort((a, b) -> a - b);   // ascending

// forEach: side-effect per element
nums.forEach(n -> Console.println(n));

Immediately-invoked lambdas

You can define and call a lambda in one expression by wrapping it in parentheses and adding the call parentheses:

int result = ((int a, int b) -> a + b)(3, 4);
Console.println(result);   // 7

This is occasionally useful for one-off computations where you want a local scope, or for initializing a const from a non-trivial expression.

Lambdas vs methods

Lambdas and methods both represent reusable behavior, but they serve different purposes. Methods are named members of a class, accessible wherever the class is visible. Lambdas are anonymous values, scoped to wherever the variable holding them is visible. Use methods when the behavior is part of a type's API and will be called from many places; use lambdas when the behavior is local to one piece of code (like a one-off transformation passed to map).
