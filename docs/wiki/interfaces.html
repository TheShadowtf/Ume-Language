Interfaces & Abstract Classes

Interfaces define a contract — a set of method signatures that a class promises to implement. A class can implement multiple interfaces, which is Ume's mechanism for multi-type polymorphism (since single inheritance applies to classes). This page covers interface declaration, implementation, default methods, and how interfaces differ from abstract classes.

Declaring an interface

An interface is declared with the interface keyword. Inside the body you list method signatures — return type, name, parameters — without bodies (terminated by a semicolon). A class declares that it implements an interface with the implements keyword.

public interface IDrawable {
    func void draw();
    func void resize(double factor);
}

public interface IClickable {
    func void onClick();
}

public class Button implements IDrawable, IClickable {
    @Override
    public func void draw() {
        Console.println("[Button Drawn]");
    }

    @Override
    public func void resize(double factor) {
        Console.println("Resized by " + factor);
    }

    @Override
    public func void onClick() {
        Console.println("Button Clicked");
    }
}

A class can implement multiple interfaces (comma-separated after implements), and can also extend a base class at the same time. The class must provide an implementation for every abstract method declared in every interface it implements. In Ume, implementing interface methods requires the override keyword or the @Override annotation.

@FunctionalInterface

You can annotate an interface with @FunctionalInterface to declare that it is intended as a single-abstract-method (SAM) interface (ideal for lambda targets). The compiler and interpreter strictly verify that exactly one abstract method is present. If zero or multiple abstract methods exist, an error is reported at compile time.

@FunctionalInterface
public interface Transformer {
    func string transform(string input);
}

Using interfaces as types

An interface is a type. You can declare variables, parameters, and fields of an interface type, and assign any object whose class implements that interface. Method calls through an interface variable dispatch to the actual runtime class's implementation.

IDrawable d = new Button();
d.draw();        // calls Button.draw()
d.resize(2.0);   // calls Button.resize()

// A function that accepts any IDrawable
func void renderTwice(IDrawable item) {
    item.draw();
    item.draw();
}

renderTwice(new Button());

Default method implementations

An interface method can include a body (a "default method"). When it does, classes that implement the interface inherit that default implementation unless they override it. This lets you add new methods to an interface without breaking existing implementers.

public interface IGreeter {
    func string name();

    // Default implementation — uses name()
    func string greet() {
        return "Hello, " + name() + "!";
    }
}

public class EnglishGreeter implements IGreeter {
    @Override
    public func string name()  { return "World"; }
    // inherits the default greet()
}

public class FancyGreeter implements IGreeter {
    @Override
    public func string name()  { return "Alice"; }

    @Override
    public func string greet() { return $"✨ Hi there, {name()}! ✨"; }   // override default
}

Interface constants

Interfaces can declare constants with const. These are implicitly public static final and must be initialized. They're useful for interface-related configuration values.

public interface Config {
    const int MAX_CONNECTIONS = 10;
    const string DEFAULT_HOST = "localhost";
}

Console.println(Config.MAX_CONNECTIONS);   // 10

Generic interfaces

Interfaces can be parameterized over types, just like classes. Type parameters go in angle brackets after the interface name.

public interface Comparable<T> {
    func int compareTo(T other);
}

public class Temperature implements Comparable<Temperature> {
    public double celsius;

    public Temperature(double c) { this.celsius = c; }

    public func int compareTo(Temperature other) {
        if (this.celsius < other.celsius) return -1;
        if (this.celsius > other.celsius) return 1;
        return 0;
    }
}

Interfaces vs abstract classes

Both define contracts that other types must fulfill, but they differ in important ways:

InterfaceAbstract class
InheritanceA class can implement many.A class can extend one.
StateNo instance fields (only constants).Can have instance fields.
ConstructorsNone.Can have constructors (called via super).
Default methodsYes.Yes (abstract methods can sit alongside concrete ones).
Use when…You want to describe a capability that unrelated types can have.You want to share implementation among closely related types.

A common pattern is to use an abstract class for the shared base (with fields and partial implementation) and interfaces for the orthogonal capabilities. For example, an Animal abstract class might hold the name and age fields, while IDrawable and IClickable interfaces describe capabilities that some animals (but not others) have.

Multiple interface inheritance

A class can implement several interfaces. If two interfaces declare a method with the same signature, the class's single implementation satisfies both. If two interfaces declare a method with the same name but different signatures, they're treated as overloads.

public interface A { func void ping(); }
public interface B { func void ping(); }

public class C implements A, B {
    public func void ping() {
        Console.println("pong");   // satisfies both A.ping and B.ping
    }
}

A a = new C();
B b = new C();
a.ping();   // pong
b.ping();   // pong
