Getting Started

Build the compiler, write your first program, and learn the project layout and CLI.

Prerequisites

To compile and run Ume, you need CMake and a C++ toolchain (Visual Studio with C++ on Windows):

ToolVersionPurpose
Visual Studio2022+ (Community OK)MSVC C++ compiler + Windows SDK
CMake3.20+Build system generator
GitAnyClone the repository
1-Line Setup for New Windows PCs

If you don't have Visual Studio or CMake installed yet, you can install both in one command via Windows Package Manager (PowerShell / Command Prompt):

winget install Kitware.CMake && winget install Microsoft.VisualStudio.2022.Community --override "--add Microsoft.VisualStudio.Workload.NativeDesktop --passive"

⚡ One-Click Automated Build (build.bat)

Clone the repository and run build.bat. The automated script automatically discovers CMake and Visual Studio C++ toolchains, initializes environment variables, compiles the compiler (ume.exe), interpreter, and graphics subsystems in Release mode, and deploys everything to bin\release\.

git clone https://github.com/your-org/ume-language.git
cd ume-language
.\build.bat

Hello, World

Create a file called hello.ume. Ume programs declare their entry point with public static func void main() inside class Main:

public class Main {
    public static func void main() {
        Console.println("Hello, World!");
    }
}

Run it two ways. During development you'll usually interpret directly with -run — it skips native code generation and starts immediately, which makes iteration fast. When you want a shippable binary, use -compile to transpile to C++17 and invoke the host C++ compiler:

# Interpret directly (fast for development)
ume.exe -run hello.ume

# Or compile to a native binary
ume.exe -compile hello.ume -o hello
.\hello.exe

CLI reference

The ume command takes a subcommand-style flag. -run and -compile are the two you'll use most; the others scaffold and manage projects.

CommandDescription
ume -run file.umeInterpret and run a .ume file directly (no binary output).
ume -compile file.umeTranspile to C++17 and invoke the host compiler. Produces a native binary.
ume -compile file.ume -o outCompile and name the output binary.
ume new MyAppScaffold a new project (creates src/, stdlib/, build.bat).
ume build [dir]Build a project in the current or given directory.
ume run [dir]Build and immediately run a project.
ume replStart an interactive read-eval-print loop.
ume version / -vPrint version information.
ume helpShow help.

Project structure & ume.toml

A scaffolded Ume project contains a ume.toml configuration manifest, an entry point in src/, and an automated build directory. Projects can configure compiler backends and asset copying pipelines (e.g. assets = "textures, audio") directly in ume.toml.

MyApp/
├── ume.toml          ← Project manifest (entry, backend, assets)
├── src/
│   └── main.ume      ← Main entry point
└── build/            ← Compiled binaries & copied assets

For complete details on configuration options, asset mapping syntax (src -> dst), and project commands, see the Projects & ume.toml guide.

Importing modules

Ume has two complementary mechanisms for bringing in external code. The first is the AST-level import statement, which resolves packages by name and injects only the requested symbols. The second is the C-style #include preprocessor directive, which textually splices a file's source into yours before lexing.

import std.collections.*;
import std.thread.*;
import std.math.*;

public class Main {
    public static func void main() {
        var nums = new List<int>();
        nums.add(42);
        Console.println(nums.size());
    }
}

The details — package declarations, namespace blocks, selective symbol imports, wildcards, include guards, and when to use each mechanism — are covered in depth on the Modules & Imports page.

Tip

During development prefer -run. Switch to -compile only when you need a distributable binary or want to measure real performance.
