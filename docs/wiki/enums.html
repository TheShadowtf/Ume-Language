Enums & Structs

Two more user-defined types: enum for a fixed set of named values, and struct for lightweight value-type aggregates. Both have specific use cases where they're preferable to classes.

Basic enum

An enum declares a named type with a fixed set of values. The values are listed inside the body, comma-separated. By default they're auto-numbered starting from 0, but you can assign explicit values.

public enum Direction {
    North, South, East, West
}

Direction d = Direction.North;
Console.println(d);   // North

Explicit values

Assign a specific integer to an enum value with =. Values don't need to be consecutive or ordered.

public enum Status {
    Active   = 1,
    Inactive = 2,
    Deleted  = 99
}

Status s = Status.Deleted;
Console.println(s);   // Deleted

Enums with methods

An enum can have methods and fields, just like a class. Separate the value list from the methods with a semicolon. This lets you attach behavior to enum values.

public enum HttpStatus {
    Ok = 200,
    NotFound = 404,
    ServerError = 500;

    public func bool isSuccess() {
        // Inside enum methods, enum values (Ok, NotFound, etc.)
        // are accessible by their bare name.
        return this == Ok;
    }
}

HttpStatus s = HttpStatus.Ok;
Console.println(s.isSuccess());   // true

HttpStatus s = HttpStatus.Ok;
Console.println(s.isSuccess());   // true

Switching on enums

Enums and switch are a natural pair. You can switch on an enum value and dispatch to per-value behavior. A default case is recommended for forward compatibility (new values added later).

public func string describe(Direction d) {
    switch (d) {
        case Direction.North: return "up";
        case Direction.South: return "down";
        case Direction.East:  return "right";
        case Direction.West:  return "left";
        default:              return "unknown";
    }
}

Structs

A struct is a lightweight aggregate type — a bundle of named fields. Like a class, it can have fields and methods, but it has value-type semantics: assigning a struct copies the value rather than sharing a reference. Use structs for small, immutable-ish data bundles where copy semantics are natural — points, colors, configuration records.

public struct Point {
    public double x;
    public double y;

    public func double distance(Point other) {
        double dx = x - other.x;
        double dy = y - other.y;
        return Math.sqrt(dx*dx + dy*dy);
    }
}

Point p1 = new Point();
p1.x = 0.0;
p1.y = 0.0;

Point p2 = new Point();
p2.x = 3.0;
p2.y = 4.0;

Console.println(p1.distance(p2));   // 5.0

Struct initializers

You can create a struct instance and set its fields in one expression using the struct initializer syntax. There are two equivalent forms — one uses = after each field name (postfix, typed), the other uses : (bare, untyped). The typed form is more common because it reads naturally and works as a primary expression.

// Postfix form: Type { field = value, field = value, ... }
Point p = Point { x = 10.0, y = 20.0 };

// Bare form: { field: value, field: value, ... }
Point q = { x: 1.0, y: 2.0 };

Console.println(p.x);   // 10.0
Console.println(q.y);   // 2.0

Struct vs class

structclass
SemanticsValue type — assignment copies.Reference type — assignment shares.
AllocationTypically on the stack (when local).Always on the heap (via new).
InheritanceCannot extend or be extended.Single inheritance via extends.
Use whenSmall data bundle, copy semantics desired.Anything with identity or shared mutable state.

A useful rule of thumb: if two variables holding the "same" value should still be independent (modifying one doesn't affect the other), use a struct. If they should share state, use a class.
