Attributes

Attributes are metadata attached to declarations. They sit in square brackets above the declaration and are read by the compiler to drive code generation — most importantly, [Serializable] and [JsonProperty] which together trigger automatic JSON serialization code generation.

Syntax

An attribute is written as [Name] or [Name(args)], placed immediately before the declaration it applies to. Multiple attributes can be stacked — either as separate [Attr1] [Attr2] lines or comma-separated inside one set of brackets: [Attr1, Attr2]. Attributes can be applied to classes, fields, methods, and enums.

[Serializable]
public class User {
    [JsonProperty("user_id")]
    public int id;

    [JsonProperty("username")]
    public string name;

    public double score;
}

[Serializable]

Applying [Serializable] to a class tells the compiler to generate two methods automatically:

  • toJsonString() — serializes the instance to a JSON string.
  • fromJsonString(string json) — static method that parses a JSON string and returns a new instance.

Every public field becomes a key in the JSON object. The key defaults to the field's name; use [JsonProperty] to override it. This is zero-overhead in the sense that the serialization code is generated at compile time — there's no runtime reflection.

[Serializable]
public class Product {
    [JsonProperty("product_id")]
    public int id;

    [JsonProperty("display_name")]
    public string name;

    [JsonProperty("price_usd")]
    public double price;
}

func void main() {
    var p = new Product();
    p.id    = 101;
    p.name  = "Widget";
    p.price = 19.99;

    // Serialize to JSON
    string json = p.toJsonString();
    Console.println(json);
    // {"product_id":101,"display_name":"Widget","price_usd":19.99}

    // Deserialize back
    var p2 = Product.fromJsonString(json);
    Console.println(p2.name);    // Widget
    Console.println(p2.price);   // 19.99
}

[JsonProperty("key")]

Applied to a field, [JsonProperty] overrides the JSON key used for that field during serialization and deserialization. The argument is a string literal. This is essential when your field names don't match the JSON schema you need to interoperate with — for example, when the JSON uses snake_case but your Ume fields use camelCase, or when the JSON uses an opaque identifier like "_id".

Fields without [JsonProperty]

A field in a [Serializable] class that doesn't have a [JsonProperty] attribute uses its own field name as the JSON key. In the example above, score would serialize as "score":... rather than being excluded.

Custom attributes

Attribute syntax supports any name, so you can attach arbitrary metadata to declarations for your own tooling or code generators to consume. The built-in compiler currently only acts on [Serializable] and [JsonProperty]; unknown attributes are stored on the AST but don't trigger any code generation. They're available to custom passes or external tools that read the AST.

[Experimental]
[Deprecated("use NewClass instead")]
public class OldClass {
    [Range(0, 100)]
    public int percentage;
}

Stacking attributes

You can apply multiple attributes to the same declaration. They can be on separate lines or combined in one bracket group with commas:

// Two equivalent forms:
[Serializable]
[Obsolete]
public class OldModel { /* ... */ }

[Serializable, Obsolete]
public class OldModel2 { /* ... */ }
