Operator Overloading

You can teach your own types to respond to +, -, *, comparison, and other operators by declaring operator methods inside the class. This is the standard way to make numeric-like types (vectors, matrices, complex numbers, money) read naturally in expressions.

Declaring an operator

An operator method is declared with the operator keyword, followed by the operator symbol, a parameter list, an optional return type after ->, and a body. The left operand is this; the right operand is the parameter. Operators are always public instance methods.

public class Vec2 {
    public double x, y;

    public Vec2(double x, double y) { this.x = x; this.y = y; }

    // Binary +
    public operator + (Vec2 other) -> Vec2 {
        return new Vec2(x + other.x, y + other.y);
    }

    // Binary -
    public operator - (Vec2 other) -> Vec2 {
        return new Vec2(x - other.x, y - other.y);
    }

    // Comparison
    public operator == (Vec2 other) -> bool {
        return x == other.x && y == other.y;
    }

    public func string toString() {
        return "(" + x + ", " + y + ")";
    }
}

var a = new Vec2(1.0, 2.0);
var b = new Vec2(3.0, 4.0);

var c = a + b;             // calls a.operator+(b)
Console.println(c.toString());   // (4.0, 6.0)

Console.println(a == b);   // false
Console.println(a == a);   // true

Operators with scalar operands

The right-hand operand doesn't have to be the same type as the left. This is how you'd let Vec2 * double scale a vector by a number:

public class Vec2 {
    public double x, y;

    public Vec2(double x, double y) { this.x = x; this.y = y; }

    // Vec2 * double → Vec2
    public operator * (double scalar) -> Vec2 {
        return new Vec2(x * scalar, y * scalar);
    }
}

var v = new Vec2(1.0, 2.0);
var doubled = v * 3.0;
Console.println(doubled.toString());   // (3.0, 6.0)

A more complete example: complex numbers

public class Complex {
    public double real;
    public double imag;

    public Complex(double r, double i) { real = r; imag = i; }

    public operator + (Complex o) -> Complex {
        return new Complex(real + o.real, imag + o.imag);
    }

    public operator * (Complex o) -> Complex {
        return new Complex(
            real * o.real - imag * o.imag,
            real * o.imag + imag * o.real
        );
    }

    public operator == (Complex o) -> bool {
        return real == o.real && imag == o.imag;
    }

    public func string toString() {
        return real + " + " + imag + "i";
    }
}

var z1 = new Complex(1, 2);   // 1 + 2i
var z2 = new Complex(3, 4);   // 3 + 4i

var sum = z1 + z2;            // 4 + 6i
var prod = z1 * z2;           // (1*3 - 2*4) + (1*4 + 2*3)i = -5 + 10i

Console.println(sum.toString());    // 4 + 6i
Console.println(prod.toString());   // -5 + 10i

Design guidelines

  • Only overload operators when the meaning is obvious. Vec2 + Vec2 clearly means vector addition. Account + Account does not clearly mean anything — use a named method instead.
  • Keep operator behavior consistent with the built-in types. + should add and return a new value, not mutate this. == should be symmetric (a == b implies b == a) and should agree with !=.
  • Implement == and != together — it's confusing if only one is defined.
  • Don't overload comparison operators to mean something other than ordering. < should be a total order; if you can't provide one, use a named compareTo method instead.
Operator overloading is not for everything

Resist the temptation to overload operators just because you can. For most types, named methods are clearer. Save operator overloading for types that are mathematically numeric (vectors, matrices, complex numbers, fractions, money) — there, the infix notation genuinely improves readability.
