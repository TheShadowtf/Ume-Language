Variables & Scope

Variables in Ume are declared with either an explicit type or var for type inference. Once declared, a variable's type is fixed — Ume is statically typed, and var is a convenience, not dynamic typing.

Explicit type declaration

Write the type, then the name, then optionally an initializer. The initializer's type must be assignable to the declared type. If you omit the initializer, the variable is default-initialized (zero for numerics, false for bool, null for references).

int    age    = 30;
double pi     = 3.14159;
string name   = "Alice";
bool   ready  = true;
char   grade  = 'A';

List<int> nums = new List<int>();

// Multiple variables of the same type in one statement
int a = 1, b = 2, c = 3;

// Without initializer — default-initialized
int count;
Console.println(count);   // 0

Type inference with var

When you write var instead of a type, the compiler infers the type from the initializer. The inferred type is the static type of the initializer expression — there's no "common supertype" guessing. var is purely a syntactic convenience; the compiled code is identical to writing the inferred type out by hand. auto is accepted as an alias for var.

var name   = "Alice";      // type: string
var age    = 30;            // type: int
var pi     = 3.14159;       // type: double
var nums   = new List<int>();
var person = new User();

// var requires an initializer — the type has to come from somewhere
// var x;   // ← error: cannot infer type without initializer

Inference is especially useful with generics, where writing the full type is verbose:

var scores = new Map<string, int>();
scores.put("Alice", 95);

// Equivalent explicit form:
// Map<string, int> scores = new Map<string, int>();

const variables

A const variable cannot be reassigned after initialization. The value itself is not necessarily deeply immutable — if you have a const List<int>, you can still call add() on it; you just can't make the variable point at a different list. Use const for values that should not change, like configuration constants or computed results you want to cache.

const int MAX_RETRIES = 3;
const string APP_NAME = "MyApp";
const double PI_OVER_2 = Math.PI / 2.0;

// MAX_RETRIES = 5;   // ← error: cannot assign to const

// The binding is const, not the object:
const List<int> fixed = new List<int>();
fixed.add(1);          // OK — mutating the list, not rebinding the variable
// fixed = new List<int>();  // ← error: cannot rebind const

Scope

Variables are block-scoped. A block is anything between matching { } — a function body, an if body, a loop body, or a standalone { } block. A variable declared inside a block is not visible outside it. Inner blocks can shadow outer variables with the same name, though this is discouraged for readability.

func void demo() {
    int x = 1;            // visible in the whole function body

    if (true) {
        int y = 2;        // visible only inside this if-block
        int x = 10;       // shadows the outer x — legal but confusing
        Console.println(x);   // 10
    }

    // Console.println(y);  // ← error: y is not in scope here
    Console.println(x);       // 1 (the outer x is unchanged)
}

Loop variables are scoped to the loop body, not the enclosing block:

for (int i = 0; i < 3; i++) {
    Console.println(i);
}
// Console.println(i);   // ← error: i is not visible here

foreach (string n in names) {
    Console.println(n);
}
// Console.println(n);   // ← error: n is not visible here

Fields vs locals

Variables declared inside a class body (outside any method) are fields — they live on each instance of the class (or on the class itself if static). Variables declared inside a method, constructor, or lambda are locals — they live on the call stack and disappear when the method returns.

class Counter {
    public int count = 0;          // field — one per instance

    public func void increment() {
        int step = 1;              // local — fresh on each call
        count = count + step;
    }
}

Fields can have initializers that run when the object is constructed, and they default to a zero/null value if you don't provide one. Locals do not get a default zero value in safe code — you must assign them before reading.

Assignment and compound assignment

The basic assignment operator = stores a value into an existing variable or field. The compound forms +=, -=, *=, /=, %= combine an arithmetic operation with assignment — x += 5 is exactly equivalent to x = x + 5 but more concise and slightly more efficient for complex left-hand sides.

int x = 10;
x += 5;    // x is now 15
x -= 3;    // x is now 12
x *= 2;    // x is now 24
x /= 4;    // x is now 6
x %= 4;    // x is now 2

Increment and decrement are available as both prefix (++x, returns the new value) and postfix (x++, returns the old value). They modify the variable in place.

int i = 0;
int a = i++;   // a = 0, i = 1  (postfix: returns old value)
int b = ++i;   // b = 2, i = 2  (prefix: returns new value)
