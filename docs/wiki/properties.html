Properties & Indexers

Properties look like fields to callers but execute code on read and write. They're the idiomatic way to expose computed values, validate assignments, or hide an internal storage format behind a clean public API. Indexers are the same idea but with [] syntax instead of a named accessor.

Full get/set property

A property is declared with a type, a name, and a body containing get and/or set accessors. The get accessor returns the property's value; the set accessor receives the new value in a special value variable. A property with only get is read-only; one with only set is write-only (rare).

public class Player {
    private int _hp = 100;

    public int Health {
        get { return _hp; }
        set {
            if (value < 0) value = 0;     // clamp on assignment
            _hp = value;
        }
    }
}

var p = new Player();
p.Health = 150;        // calls set with value=150
Console.println(p.Health);  // 150
p.Health = -10;        // clamped to 0
Console.println(p.Health);  // 0

Read-only property

Omit the set accessor to make a property read-only from the outside. The class itself can still modify the backing field directly.

public class Config {
    private string _host;
    public Config(string h) { _host = h; }

    public string Host {
        get { return _host; }
        // no set — callers cannot change Host
    }
}

var c = new Config("localhost");
Console.println(c.Host);     // localhost
// c.Host = "remote";        // ← compile error: no setter

Expression-bodied property =>

For properties whose getter is a single expression, use the fat-arrow => followed by the expression and a semicolon. This is the most concise form and is preferred for computed properties. The result is always read-only (there's no setter).

public class Circle {
    public double radius;

    public double Area => Math.PI * radius * radius;
    public double Circumference => 2.0 * Math.PI * radius;
    public bool IsUnit => radius == 1.0;
}

var c = new Circle();
c.radius = 5.0;
Console.println(c.Area);          // 78.54...
Console.println(c.Circumference); // 31.42...

Auto-property

If you don't need any logic in the getter or setter, write get; and set; (with semicolons instead of bodies). The compiler generates a hidden backing field automatically. This gives you a property that behaves like a public field but can later be upgraded to a full property without breaking callers.

public class User {
    public string Name { get; set; }
    public int    Age  { get; set; }
}

var u = new User();
u.Name = "Alice";
u.Age  = 30;
Console.println(u.Name);   // Alice

Property initializer

You can give a property a default value with = expr after the closing brace. This runs when the object is constructed, before any constructor body. Combined with auto-properties, this lets you declare a public settable field with a default in one line.

public class Settings {
    public int  Timeout { get; set; } = 30;
    public bool Verbose { get; set; } = true;
}

var s = new Settings();
Console.println(s.Timeout);   // 30
Console.println(s.Verbose);   // true

Expression-bodied accessors

Inside a full property body, the get and set accessors can themselves use the fat-arrow form for one-expression bodies:

public class Temperature {
    public double celsius;

    public double fahrenheit {
        get => celsius * 9.0 / 5.0 + 32.0;
        set => celsius = (value - 32.0) * 5.0 / 9.0;
    }
}

var t = new Temperature();
t.celsius = 100;
Console.println(t.fahrenheit);   // 212
t.fahrenheit = 32;
Console.println(t.celsius);      // 0

Static properties

A property marked static belongs to the class, not to instances. Access it through the class name. The get/set accessors can only reference other static members.

public class App {
    private static int _count = 0;

    public static int Count {
        get { return _count; }
        set { _count = value; }
    }
}

App.Count = 42;
Console.println(App.Count);   // 42

Indexers this[i]

An indexer lets instances of your class be indexed with square brackets, like an array. Declare it with this[params] and get/set accessors, exactly like a property but parameterized. The parameter(s) can be any type — not just int.

public class WordList {
    private List<string> words = new List<string>();

    public func void add(string w) { words.add(w); }

    public string this[int index] {
        get { return words.get(index); }
        set { words.set(index, value); }
    }
}

var wl = new WordList();
wl.add("Hello");
wl.add("World");

Console.println(wl[0]);   // Hello  (calls get)
wl[1] = "Ume";            // calls set with value="Ume"
Console.println(wl[1]);   // Ume

Multi-parameter indexers

An indexer can take multiple parameters, separated by commas. This is useful for matrix-like types where you index by row and column.

public class Matrix {
    private double[] data;
    private int rows, cols;

    public Matrix(int rows, int cols) {
        this.rows = rows;
        this.cols = cols;
        this.data = new double[rows * cols];  // array allocation via new T[size]
    }

    public double this[int row, int col] {
        get { return data[row * cols + col]; }
        set { data[row * cols + col] = value; }
    }
}

var m = new Matrix(3, 3);
m[1, 2] = 3.14;
Console.println(m[1, 2]);   // 3.14

String-key indexers

Indexer parameters don't have to be integers — they can be any type. This is how Map<K, V> would expose bracket access if it exposed an indexer (the stdlib Map uses get/put methods instead, but the syntax would be):

public class Config {
    private Map<string, string> values = new Map<string, string>();

    public string this[string key] {
        get { return values.get(key); }
        set { values.put(key, value); }
    }
}

var cfg = new Config();
cfg["host"] = "localhost";
cfg["port"] = "8080";
Console.println(cfg["host"] + ":" + cfg["port"]);   // localhost:8080
