Projects & Tooling

Project Configuration (ume.toml)

Ume projects use a ume.toml manifest at the project root to configure project metadata, entry points, compilation backends, and asset bundling pipelines.

Scaffolding a new project

To scaffold a fresh project with standard directory structure, run ume new <ProjectName>:

ume new MyGame
cd MyGame

This creates the standard Ume project structure:

MyGame/
├── ume.toml          ← Project configuration file
├── src/
│   └── main.ume      ← Entry point source file
├── build/            ← Generated binaries & copied assets
└── .gitignore        ← Ignores build/ and binaries

ume.toml Reference

A complete ume.toml file supports the following keys:

name    = "MyGame"
version = "1.0.0"

# Path to the main entry point .ume file (relative to project root)
entry   = "src/main.ume"

# Compiler backend: "cpp" (default) or "llvm" (requires clang on PATH)
backend = "cpp"

# Asset bundling pipeline: folders, files, or explicit rename mappings
assets  = "textures, shaders, audio, config/game.json -> game.json"

Configuration Keys & Options

Key Type Default Description
name string "out" The name of the compiled binary output (e.g. produces build/MyGame.exe).
version string "1.0.0" SemVer version string for your application or package.
entry string "src/main.ume" Path to the main .ume source file containing the public static func void main() entry point.
backend string "cpp" The transpiler backend: "cpp" (transpiles to C++17 and invokes MSVC/Clang) or "llvm" (LLVM IR).
assets string "" Comma-separated list of folders and files to automatically copy into build/ during ume build. Supports direct copies and rename/target mappings (src -> dst).

Asset Bundling Pipeline (assets)

When compiling games, GUI applications, or web servers, your compiled executable usually needs runtime assets (textures, audio files, configuration files, 3D models, shaders) placed next to it in the build/ directory.

Ume provides a built-in asset copy pipeline via the assets configuration key:

1. Direct Directory / File Copy

Specifying a folder or file name copies it directly into build/ with the same relative name:

assets = "textures, audio, shaders, icon.png"

When you run ume build, the compiler will automatically copy:

  • textures/ → build/textures/
  • audio/ → build/audio/
  • shaders/ → build/shaders/
  • icon.png → build/icon.png

2. Source-to-Destination Mapping (src -> dst)

You can also map a source path to a custom destination subfolder inside build/ using the arrow (->) syntax:

assets = "resources/assets -> assets, config/release_settings.json -> settings.json"
  • Copies resources/assets/ into build/assets/
  • Copies config/release_settings.json into build/settings.json

3. Mixed Asset Declarations

You can freely combine simple names and arrow mappings in a single comma-separated string:

name    = "MinecraftClone"
entry   = "src/main.ume"
backend = "cpp"
assets  = "assets, shaders -> shaders, config/blocks.json -> blocks.json"

Building & Running Projects

ume build [projectDir]

Compiles the project specified by ume.toml and copies all declared assets into the build/ folder:

ume build

ume run [projectDir]

Interprets and immediately runs the project using the entry file specified in ume.toml:

ume run
Asset Deployment Guarantee

All directory hierarchies are preserved recursively, and existing files in build/ are cleanly overwritten with the newest versions upon every ume build.
