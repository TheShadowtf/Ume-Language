Expressions & Operators

Everything that produces a value — arithmetic, comparison, logical combination, casting, null handling — is an expression in Ume. This page lists every operator with semantics, examples, and the precedence rules that govern how they combine.

Arithmetic operators

The five basic arithmetic operators work on all numeric types. Integer division truncates toward zero (so 7 / 2 is 3, not 3.5). The modulo operator % returns the remainder of integer division and follows the sign of the dividend.

OperatorMeaningExample
+Addition3 + 4 → 7
-Subtraction (binary) / negation (prefix)10 - 4 → 6, -x
*Multiplication3 * 4 → 12
/Division10 / 3 → 3 (int), 10.0 / 3 → 3.333…
%Modulo (remainder)10 % 3 → 1
 
int    a = 17 / 5;     // 3  (truncated)
double b = 17.0 / 5;   // 3.4
int    c = 17 % 5;     // 2
int    d = -17 % 5;    // -2 (sign of dividend)

Comparison operators

All six comparison operators produce a bool. They work on any type that defines them — for user-defined types via operator overloading. Equality on strings compares contents, not reference identity.

OperatorMeaning
==Equal
!=Not equal
<Less than
>Greater than
<=Less than or equal
>=Greater than or equal
 
bool a = (3 < 5);          // true
bool b = (10 == 10);      // true
bool c = ("hi" == "hi");  // true  (string content equality)
bool d = (3.14 != 3.14);  // false

Logical operators

The logical operators operate on bool values and short-circuit: && does not evaluate its right operand if the left is false, and || does not evaluate its right operand if the left is true. This makes them safe for null checks like x != null && x.size() > 0.

OperatorMeaning
&&Logical AND (short-circuit)
||Logical OR (short-circuit)
!Logical NOT (prefix)
 
string? name = getName();
if (name != null && name.length() > 0) {
    Console.println(name);
}

bool ok = (x > 0) || (y > 0);   // true if either is positive
bool neg = !ok;                  // logical negation

Bitwise operators

For low-level integer manipulation. These operate bit-by-bit on integer operands.

OperatorMeaning
&Bitwise AND
|Bitwise OR
^Bitwise XOR
~Bitwise NOT (prefix, one's complement)
<<Left shift
>>Right shift
 
int mask  = 0xFF;
int flags = 0b1010;
int set   = flags | 0b0100;   // 0b1110  — set bit 2
int clr   = flags & ~0b0010;  // 0b1000  — clear bit 1
int tog   = flags ^ 0b0010;   // 0b1000  — toggle bit 1
int hi    = 1 << 8;           // 256
int half  = 1024 >> 1;        // 512

Assignment operators

Basic assignment = stores the right-hand value into the left-hand target. The compound forms combine an arithmetic or bitwise operation with assignment.

OperatorEquivalent to
=(plain assignment)
+=x = x + y
-=x = x - y
*=x = x * y
/=x = x / y
%=x = x % y

Increment / decrement

Both prefix and postfix forms are available. Prefix returns the new value; postfix returns the old value. They modify the operand in place and require an lvalue (a variable or field) as the operand.

int i = 5;
int a = i++;   // a = 5, i = 6  (postfix returns old)
int b = ++i;   // b = 7, i = 7  (prefix returns new)
i--;
--i;

Ternary conditional ?:

The conditional expression evaluates a boolean condition and yields one of two values depending on the result. It's right-associative, so you can chain them, but doing so usually hurts readability — prefer switch or early return for more than two branches.

int x = 10;
string label = x > 0 ? "positive" : "non-positive";

// Nested ternary (right-associative)
string sign = x > 0 ? "positive" : (x < 0 ? "negative" : "zero");

Null-safety operators

Ume has three operators for working with nullable values safely and concisely.

?? — null-coalescing

Evaluates the left operand; if it's non-null, returns it; otherwise evaluates and returns the right operand. This is the idiomatic way to provide a default for a nullable value.

string? name = getName();
string display = name ?? "Anonymous";   // "Anonymous" if name was null

// Chains work: first non-null wins
string? a = null;
string? b = null;
string? c = "c";
string first = a ?? b ?? c ?? "none";   // "c"

?. — safe navigation

A method or field access through ?. returns null immediately if the object on the left is null, instead of throwing a null-reference error. If the object is non-null, it behaves like a regular . access. The result type is the nullable form of whatever the access would normally return.

string? name = getName();
int? len = name?.length();   // null if name is null, else the length

// Chained — short-circuits at the first null
class User {
    public Address? address;
}
class Address {
    public string city;
}

User? u = getUser();
string? city = u?.address?.city;   // null if u, u.address, or city is null

! — null-assertion

The postfix ! operator asserts that a nullable value is non-null. If it's actually null at runtime, an exception is thrown. Use it when you know more than the type system does — for example, after a null check that the compiler can't see through, or when an external contract guarantees non-null.

string? maybeName = getNameFromCache();
string name = maybeName!;   // asserts non-null, throws if null

// Often combined with ?. to assert at the end of a safe chain
int len = maybeName!.length();

cast<T>(expr) and expr as T

Two ways to convert between types. cast<T>(expr) is the function-style form; expr as T is the infix form. Both produce a value of type T. The cast is checked at runtime — if the value isn't actually convertible to T, an exception is thrown. Use casts when you have an any or a base type and need to recover a more specific type.

any box = 42;
int n = cast<int>(box);        // function-style cast
int m = box as int;            // infix cast — same result

class Animal { }
class Dog extends Animal { public string breed; }

Animal a = new Dog();
Dog d = cast<Dog>(a);          // downcast — checked at runtime
Console.println(d.breed);

new — object creation

Allocates a new instance of a class and calls its constructor. Generic type arguments go in angle brackets after the class name. Constructor arguments go in parentheses.

var p   = new Point(3.0, 4.0);
var lst = new List<int>();
var map = new Map<string, int>();
var box = new Box<int>(42);

Member access and indexing

The dot . accesses fields, properties, and methods on an object. The index [expr] accesses elements of an array, list, map, or any type that defines an indexer.

class Vec { public double x; }
Vec v = new Vec();
v.x = 1.5;            // field access
double val = v.x;     // field read

int[] arr = [10, 20, 30];
int first = arr[0];   // indexing
arr[1] = 99;          // index assignment

Function and method calls

Call a function by writing its name (or an expression yielding a function value) followed by parenthesized arguments. Method calls use dot syntax. Generic type arguments can be specified explicitly when they can't be inferred.

int s = add(3, 4);                  // function call
Console.println("hi");             // static method call
int len = name.length();           // instance method call

// Explicit generic type arguments
List<int> evens = nums.filter<int>(n -> n % 2 == 0);

Lambda expressions

Lambdas are expressions that produce function values. They're covered in depth on the Lambdas & Closures page. The short form: (params) -> { body } or x -> expr for a single parameter and expression body.

var add = (int a, int b) -> { return a + b; };
var sq  = n -> n * 2;       // single param, expression body
var noop = () -> { Console.println("hi"); };     // no params

Operators are listed from highest to lowest binding precedence. Within the same level, associativity is as noted. Parentheses always override precedence.

// Examples showing precedence
int a = 1 + 2 * 3;        // 7 — * binds tighter than +
int b = (1 + 2) * 3;      // 9 — parens override
bool c = !true || false;  // false — ! binds tighter than ||
int d = 1 << 2 + 1;       // 8 — + binds tighter than <<, so (1 << (2+1))
bool e = a == 7 && b == 9; // true — == binds tighter than &&
