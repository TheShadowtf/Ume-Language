Classes

Classes are the primary user-defined type in Ume. They support the full OOP feature set: fields, methods, constructors, destructors, inheritance, abstract/final modifiers, static members, and access control. This page covers the complete class system.

Declaring a class

A class is declared with the class keyword, a name, and a body in braces. Inside the body you put fields, constructors, methods, properties, operators, and indexers. Each member can have an access modifier (public, private, protected, internal) and optional modifiers (static, final, override, abstract).

public class Animal {
    public string name;
    private int age;

    public Animal(string name, int age) {
        this.name = name;
        this.age  = age;
    }

    public func string describe() {
        return name + " (age " + age + ")";
    }
}

var a = new Animal("Rex", 3);
Console.println(a.describe());   // Rex (age 3)

Access modifiers

Access modifiers control who can see a member. The default (when you omit the modifier) is package-private — visible only within the same package.

ModifierAccessible from
publicAnywhere the class is visible.
privateOnly inside the same class.
protectedThe same class and its subclasses.
internalThe same package / module.
(none)Package-private (same as internal in practice).

Constructors

A constructor is declared as a method whose name matches the class name and has no return type. Constructors run when new creates an instance. A class can have multiple constructors (overloaded by parameter list); one constructor can delegate to another with this(...).

public class Point {
    public double x;
    public double y;

    // Primary constructor
    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    // Overloaded: zero-argument, delegates to the primary
    public Point() {
        this(0.0, 0.0);
    }
}

var p1 = new Point(3.0, 4.0);
var p2 = new Point();        // (0.0, 0.0)

this

Inside an instance method or constructor, this refers to the current object. You use it to disambiguate when a parameter shadows a field name, or to pass the current object to another function. In a static method there is no this.

public class User {
    public string name;

    public User(string name) {
        this.name = name;     // 'this.name' is the field, 'name' is the param
    }

    public func User rename(string newName) {
        this.name = newName;
        return this;          // return the current object for chaining
    }
}

Inheritance

A class can extend exactly one parent class with extends. The subclass inherits all of the parent's non-private members. To call the parent's constructor, use super(args) as the first statement in the subclass's constructor. To call a parent method that you've overridden, use super.methodName(args).

public class Dog extends Animal {
    public string breed;

    public Dog(string name, int age, string breed) {
        super(name, age);      // call Animal's constructor
        this.breed = breed;
    }

    public override func string describe() {
        return super.describe() + " [" + breed + "]";
    }
}

var d = new Dog("Buddy", 4, "Labrador");
Console.println(d.describe());
// Buddy (age 4) [Labrador]

super

Two uses of super: (1) super(args) calls the parent constructor — this must be the first statement in the subclass constructor. (2) super.methodName(args) calls an inherited method that the current class has overridden, bypassing the override. You cannot use super in a static context.

override and @Override (Mandatory)

When a subclass provides a new implementation of a method inherited from its parent or an implemented interface, marking the method with override or @Override is mandatory in Ume. If an overriding method is not marked, the compiler and interpreter will reject it with an error.

Both styles are fully supported and equivalent:

  • C# / Kotlin style: public override func double area()
  • Java style: @Override public func double area()
public class Rectangle extends Shape {
    // Style 1: keyword
    public override func double area() {
        return width * height;
    }
}

public class Circle extends Shape {
    // Style 2: Java-style annotation
    @Override
    public func double area() {
        return Math.PI * radius * radius;
    }
}

// Error if omitted:
public class Triangle extends Shape {
    public func double area() { return 0.5 * b * h; }
    // error: Method 'area' overrides or implements a method in 'Shape', but is missing 'override' or '@Override'
}

Conversely, if you mark a method with override or @Override but no matching method exists in any superclass or interface (for instance due to a typo or parameter mismatch), the compiler catches it immediately.

abstract classes and methods

An abstract class cannot be instantiated directly — it can only be subclassed. An abstract method declares a signature but no body; concrete subclasses must provide an implementation, otherwise a compile-time error is raised. This is how Ume does polymorphism: you program against the abstract parent's interface, and the actual behavior comes from whichever concrete subclass is present at runtime.

public abstract class Shape {
    public abstract func double area();    // no body — subclass must implement

    public func void printArea() {
        Console.println("Area: " + area());   // calls the subclass's area()
    }
}

public class Rectangle extends Shape {
    private double w, h;
    public Rectangle(double w, double h) { this.w = w; this.h = h; }
    public override func double area() { return w * h; }
}

public class Circle extends Shape {
    public double radius;
    public override func double area() { return Math.PI * radius * radius; }
}

Shape s = new Rectangle(4.0, 5.0);
s.printArea();   // Area: 20

s = new Circle();
s.radius = 3.0;
s.printArea();   // Area: 28.27...

final

A final class cannot be subclassed. A final method cannot be overridden by subclasses. Use final when you want to prevent further extension — typically for security-sensitive classes or to enable compiler optimizations.

public final class SecretKey {
    // cannot be subclassed
}

public class Base {
    public final func void critical() {
        // subclasses cannot override this
    }
}

Static members

A static field or method belongs to the class itself, not to any particular instance. There's exactly one copy of a static field, shared by all instances. Static methods are called on the class name (ClassName.method()) and don't have access to this.

public class Counter {
    public static int total = 0;     // shared across all instances

    public int id;

    public Counter() {
        total++;                     // increment the shared counter
        this.id = total;
    }

    public static func int nextId() {
        return total + 1;            // can read static fields
        // cannot read instance fields like 'id' here
    }
}

var c1 = new Counter();
var c2 = new Counter();
Console.println(Counter.total);    // 2
Console.println(c2.id);            // 2
Console.println(Counter.nextId()); // 3

Destructors

A destructor is a method named ~ClassName() that runs when an object is garbage-collected. In Ume, since the transpilation target is C++17 with deterministic destruction (RAII), destructors run at well-defined points — when a local goes out of scope, when a container is cleared, etc. Use destructors to release non-memory resources (file handles, sockets, GL objects). They take no parameters and have no return type.

public class FileHandle {
    private any handle;

    public FileHandle(string path) {
        this.handle = openFile(path);
    }

    ~FileHandle() {
        closeFile(this.handle);
    }
}

Nested types

You can declare classes, structs, and enums inside a class body. They become members of the enclosing class and are accessed as Outer.Inner. Nested types can be static (the common case — they don't need an enclosing instance) or non-static (rare).

public class LinkedList<T> {
    public class Node {
        public T value;
        public Node next;
    }

    private Node head;
}

Multiple fields in one declaration

You can declare several fields of the same type in a single statement, separated by commas. This is purely syntactic convenience — it's equivalent to separate declarations.

public class Vec3 {
    public double x, y, z;   // three fields, all double
}
