Strings & Interpolation

Strings in Ume are double-quoted, reference-typed, and support both escape sequences and C#-style $"…{expr}…" interpolation. This page covers literal syntax, escapes, concatenation, and the interpolation grammar.

String literals

A string literal is a sequence of characters between double quotes. The lexer treats everything between the opening and closing " as the string's value, with one exception: a backslash \ starts an escape sequence.

string simple   = "Hello";
string withSpaces = "  leading and trailing  ";
string empty      = "";

Escape sequences

Inside a regular string literal, these escape sequences are recognized. Any other character after a backslash is included literally.

EscapeMeaning
\nNewline (LF, U+000A)
\tHorizontal tab (U+0009)
\rCarriage return (U+000D)
\"Double quote (so you can include " in a string)
\\Backslash (so you can include \)
\0Null character (U+0000)
 
string nl      = "first\nsecond";       // first on one line, second on the next
string quote    = "She said \"hi\".";         // She said "hi".
string winpath  = "C:\\temp\\file.txt";      // C:\temp\file.txt
string tabbed   = "col1\tcol2";                // col1<tab>col2

Concatenation

The + operator concatenates strings. When one operand is a string and the other is a non-string, the non-string is converted to its string representation via toString() automatically. This makes it easy to build messages inline:

string name = "Alice";
int    age  = 30;
double pi   = 3.14;

string msg = "Name: " + name + ", age: " + age + ", pi: " + pi;
Console.println(msg);
// Name: Alice, age: 30, pi: 3.14

For repeated concatenation in a loop, prefer StringBuilder — it's dramatically more efficient than + because + allocates a fresh string each time.

Interpolated strings $"…"

Prefix a string literal with $ to enable interpolation. Inside an interpolated string, text between { and } is parsed as a Ume expression, evaluated, and its result is converted to a string and spliced in. The expression can be any valid expression: a variable reference, an arithmetic expression, a method call, even another string.

string name = "Alice";
int    age  = 30;

string msg = $"Hello, {name}! You are {age} years old.";
Console.println(msg);
// Hello, Alice! You are 30 years old.

Interpolated strings are far more readable than chained + concatenation, especially when mixing types:

double price = 19.99;
int    qty   = 3;
double total = price * qty;

Console.println($"{qty} × ${price} = ${total}");
// 3 × $19.99 = $59.97

Expressions inside { }

The expression inside { } is a full Ume expression — it can include method calls, property accesses, arithmetic, and even nested interpolation. Braces can be nested to any depth: ${$"x={x}"} is legal (though usually a sign you should restructure).

class Point {
    public double x, y;
}

Point p = new Point();
p.x = 3.0;
p.y = 4.0;
double dist = Math.sqrt(p.x*p.x + p.y*p.y);

Console.println($"Point ({p.x}, {p.y}) has distance {dist} from origin");
// Point (3.0, 4.0) has distance 5.0 from origin

// Method calls inside { }
List<int> nums = new List<int>();
nums.add(1); nums.add(2); nums.add(3);
Console.println($"List has {nums.size()} items, sum = {nums.reduce(0, (a, n) -> a + n)}");

Literal braces in interpolated strings

If you need a literal { or } in an interpolated string (not as an expression delimiter), write it doubled: {{ produces a single {, }} produces a single }. This mirrors C# interpolated strings.

string json = $"{{\"id\": {42}, \"name\": \"Alice\"}}";
Console.println(json);
// {"id": 42, "name": "Alice"}

Escapes still work

Inside an interpolated string, the standard escape sequences (\n, \t, \", \\, etc.) work exactly as in a regular string. The backslash is processed before the { } scanner runs, so { inside an expression is unaffected by escaping.

char vs string

A single character in single quotes is a char (a value type). A single character in double quotes is a string of length 1. The two are not interchangeable — a char is not a one-character string, and concatenating a char to a string works because + auto-converts via toString().

char   ch = 'A';     // type: char
string s  = "A";     // type: string, length 1

// ch and s are different types but both convert to strings:
string msg = ch + " - " + s;     // "A - A"
